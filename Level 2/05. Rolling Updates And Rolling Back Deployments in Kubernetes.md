# Rolling Updates And Rolling Back Deployments in Kubernetes

There is a production deployment planned for next week. The Nautilus DevOps team wants to test the deployment update and rollback on Dev environment first so that they can identify the risks in advance. Below you can find more details about the plan they want to execute.


- Create a namespace `xfusion`. Create a deployment called `httpd-deploy` under this new namespace, It should have one container called `httpd`, use `httpd:2.4.25` image and `4` replicas. The deployment should use `RollingUpdate` strategy with `maxSurge=1`, and `maxUnavailable=2`. Also create a `NodePort` type service named `httpd-service` and expose the deployment on `nodePort: 30008`.

- Now upgrade the deployment to version `httpd:2.4.43` using a rolling update.

- Finally, once all pods are updated undo the recent update and roll back to the previous/original version.

## Step 1: Create Namespace

```sh
kubectl create namespace xfusion
kubectl get ns xfusion
```

## Step 2: Create Deployment (httpd:2.4.25, RollingUpdate)

**Create the deployment exactly once with the correct image and strategy.**

```sh
kubectl create deployment httpd-deploy \
  --image=httpd:2.4.25 \
  --replicas=4 \
  --namespace=xfusion \
  --dry-run=client -o yaml > httpd-deploy.yaml
```

**Now edit the file:**

```sh
vi httpd-deploy.yaml
```

**`httpd-deploy.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: httpd-deploy
  namespace: xfusion
spec:
  replicas: 4
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 2
  selector:
    matchLabels:
      app: httpd
  template:
    metadata:
      labels:
        app: httpd
    spec:
      containers:
      - name: httpd
        image: httpd:2.4.25
        ports:
        - containerPort: 80
```

**Apply deployment:**

```sh
kubectl apply -f httpd-deploy.yaml
```

**Verify deployment:**

```sh
kubectl get deployment httpd-deploy -n xfusion
kubectl get pods -n xfusion
```


## Step 3: Create NodePort Service (nodePort: 30008)

```sh
kubectl expose deployment httpd-deploy \
  --name=httpd-service \
  --type=NodePort \
  --port=80 \
  --target-port=80 \
  --namespace=xfusion \
  --dry-run=client -o yaml > httpd-service.yaml
```

**Edit the service:**

```sh
vi httpd-service.yaml
```

```yaml
apiVersion: v1
kind: Service
metadata:
  name: httpd-service
  namespace: xfusion
spec:
  type: NodePort
  selector:
    app: httpd
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30008
```

**Apply:**

```sh
kubectl apply -f httpd-service.yaml
```

**Verify:**

```sh
kubectl get svc httpd-service -n xfusion
```

## Step 4: Upgrade Deployment to httpd:2.4.43

```sh
kubectl set image deployment/httpd-deploy \
  httpd=httpd:2.4.43 \
  -n xfusion
```

**Watch rollout:**

```sh
kubectl rollout status deployment/httpd-deploy -n xfusion
```

**Check revision history:**

```sh
kubectl rollout history deployment/httpd-deploy -n xfusion
```

## Step 5: Roll Back to Previous Version (httpd:2.4.25)

**Once all pods are updated, undo the rollout:**

```sh
kubectl rollout undo deployment/httpd-deploy -n xfusion
```

**Verify rollback:**

```sh
kubectl rollout status deployment/httpd-deploy -n xfusion
kubectl rollout history deployment/httpd-deploy -n xfusion
```

**Confirm image version:**

```sh
kubectl describe deployment httpd-deploy -n xfusion | grep Image
```

**Final Validation Checklist:**

```sh
kubectl get all -n xfusion
```

**You should have:**

- Namespace: `xfusion`

- Deployment: `httpd-deploy`

- Image: `httpd:2.4.25` (after rollback)

- Replicas: `4`

- Strategy: `RollingUpdate` (`maxSurge=1`, `maxUnavailable=2`)

- Service: `httpd-service`

- NodePort: `30008`
